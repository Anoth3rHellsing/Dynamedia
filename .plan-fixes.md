# Plan: Corregir findings de verificación Dynamedia

## Contexto

La verificación estática del código fuente de Dynamedia (navegador Electron con adblocker, anti-redirecciones y descarga de medios) identificó 8 problemas: 3 bugs funcionales, 2 redundancias de código muerto, y 3 precisiones menores. Este plan corrige todos ellos en los 3 archivos fuente afectados.

## Archivos a modificar

- `main.js` — proceso principal de Electron
- `adblocker.js` — módulo de bloqueo de anuncios
- `package.json` — manifiesto del proyecto
- `renderer/index.html` — UI del renderer

## Correcciones

### 1. Race condition en `download-media` IPC handler (`main.js:117-130`)

**Problema:** El handler calcula un `savePath` único con deduplicación, pero luego llama `ses.downloadURL(url)` que dispara `will-download`, cuyo handler sobreescribe la ruta. La lógica de colisiones es código muerto.

**Fix:** Eliminar la computación de `savePath` del handler `download-media`. Dejar que `will-download` maneje la ruta exclusivamente. Retornar solo `{ ok: true, kind }` al renderer (sin `path`, ya que no es confiable). Actualizar el renderer para no mostrar una ruta específica.

### 2. Conectar `broadcastStats()` al callback del adblocker (`main.js:54-58`, `adblocker.js:98-100`)

**Problema:** `broadcastStats()` existe pero nunca se invoca. `setOnStatsChange` se exporta pero nadie lo importa. Las stats no se actualizan en tiempo real entre ventanas.

**Fix:** En `main.js`, después de `adblocker.install(ses)`, llamar `adblocker.setOnStatsChange((count) => broadcastStats(count))`. Esto conecta el pipeline completo: bloqueo → notify → callback → broadcast → todas las ventanas.

### 3. Duplicado `description` en `package.json` (líneas 4 y 7)

**Problema:** Dos claves `"description"` idénticas. JSON permite duplicados pero la segunda gana silenciosamente.

**Fix:** Eliminar la línea 7 (la segunda ocurrencia de `"description"`).

### 4. Imports no usados en `main.js` (línea 2)

**Problema:** `shell` y `dialog` se importan pero nunca se usan.

**Fix:** Remover `shell` y `dialog` del require.

### 5. Variable `win` no usada (`main.js:7`)

**Problema:** `let win = null` se declara pero `createWindow()` retorna sin asignar a `win`.

**Fix:** Eliminar la declaración `let win = null;`.

### 6. Anti-redirect `will-navigate` usa string includes impreciso (`main.js:105`)

**Problema:** `hostUrl.includes('renderer')` podría coincidir con URLs que contienen "renderer" en otra posición.

**Fix:** Cambiar a `hostUrl.endsWith('renderer/index.html')` para coincidencia exacta del path esperado.

### 7. Regex de escaneo de medios no cubre fragmentos/paths anidados (`index.html:266-267`)

**Problema:** `\.(jpe?g|png|...)(\?|$)` no matchea URLs con `#fragment` ni paths como `/image.jpg/thumbnail`.

**Fix:** Cambiar a `\.(jpe?g|png|gif|webp|bmp|avif|svg)([?#]|$)` y similar para videos: `\.(mp4|webm|mkv|mov|m4v|avi|flv)([?#]|$)`.

### 8. Security warnings aceptadas (informativo, sin cambio)

`allowpopups="true"` y falta de CSP son riesgos aceptados para un navegador. No se modifican — se documentan como decisiones conscientes.

## Verificación post-fix

1. Lanzar `./node_modules/electron/dist/electron.exe .` y confirmar que arranca sin crashes
2. Navegar a un sitio con anuncios → verificar que el contador de stats se actualiza en tiempo real
3. Abrir segunda ventana → verificar que ambas muestran stats sincronizadas
4. Escanear medios en una página con imágenes → verificar que la lista aparece correctamente
5. Descargar un medio → verificar que se guarda en la carpeta correcta (Fotos/Videos/Otros)
6. Confirmar que no hay warnings de imports no usados en consola
